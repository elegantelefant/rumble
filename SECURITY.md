# Security

## Sidecar threat model

Elefant Rumble bundles a local Python sidecar (FastAPI, `src-tauri/sidecar/`) that the Tauri host
talks to over `http://127.0.0.1:{port}`. Because the sidecar binds to localhost, any process on the
machine can reach it unless requests are authenticated.

**In scope:** another user account on the same machine. The sidecar requires a shared secret
(`x-rumble-secret` header) on every request, generated by the host and passed to the sidecar
process via the `RUMBLE_SIDECAR_SECRET` environment variable — never on the command line, since
argv is visible to any process via `ps`. A different OS user cannot read another user's process
environment (an administrator or root user can, and is out of scope along with same-user malware),
so they cannot obtain the secret and cannot call the sidecar's API.

**Out of scope:** malware or any other code already running as the same OS user as Rumble. At that
point the attacker can read the app's own environment, its keychain entries, and its local SQLite
database directly — a request secret adds no protection against that level of access.

Known issue: the secret is currently also exposed to the webview for chat streaming — see #55.

## The packaged app always requires a secret

The Tauri host generates a secret at startup and passes it to the sidecar on every spawn
(`spawn_sidecar` in `src-tauri/src/lib.rs`). The sidecar's `main.py` refuses to bind a socket at
all if it has no secret and `--dev` was not passed — it prints an error and exits non-zero, so
there is no window where a secretless sidecar is reachable in the packaged app.

## `--dev` disables authentication

`main.py --dev` starts the sidecar with no shared secret and no auth middleware at all — every
endpoint is open to any local process. This flag exists solely for `pnpm dev:sidecar`, running the
sidecar from source during development. It must never be used in a packaged build, a shared
machine, or any environment reachable by another user or process you do not fully trust. The
sidecar logs a loud warning on startup whenever it runs this way.

## Reporting a vulnerability

Please don't report security vulnerabilities in public GitHub issues.
Report them privately to dpo@elefant.legal.
